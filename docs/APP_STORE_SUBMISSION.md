> ⚠ **이 문서에 실제 계정 비밀번호를 적지 않는다.** 심사용 데모 계정 자격증명은
> placeholder로 두고, 실값은 App Store Connect 입력란에 직접 넣는다.
> (ProStore 문서에 평문 비밀번호가 커밋돼 있던 전례가 있다 — 반복하지 않는다.)

## 0. 제출 전 선행 조건

| 항목 | 상태 | 비고 |
|---|---|---|
| Apple 개발자 계정 | ❌ **미확보** | 신규 개설 대상. 드롱기 계정(ProStore) 재사용 불가 |
| `DEVELOPMENT_TEAM` | ❌ 미설정 | Team ID 수령 후 pbxproj에 주입 |
| 번들ID `com.elid.app` | ✅ 설정 완료 | 스토어 선점 여부는 등록 시점에 확인 |
| `PrivacyInfo.xcprivacy` | ✅ 생성 + Resources 등록 완료 | |
| `ITSAppUsesNonExemptEncryption` | ✅ `false` | 수출규정 질문이 뜨지 않음 |
| 기기 패밀리 | ✅ iPhone 전용 (`1`) | iPad 스크린샷 세트 불필요 |
| Associated Domains | ⏳ Team ID 대기 | `Runner.entitlements` 준비됨 |

**계정이 없으면 아래 절차를 시작할 수 없다.** 계정 확보가 첫 단계다.

## 1. 빌드·업로드

```bash
flutter build ipa --release
# 산출물: build/ios/ipa/*.ipa → Transporter 또는 Xcode Organizer로 업로드
```

버전은 `pubspec.yaml`의 `version: 1.0.0+1`을 따른다.
재업로드할 때는 **빌드번호(+뒤)만 올려도 된다.**

### 2-3. 심사용 데모 계정 — 필수

ELID는 **로그인 없이는 대부분의 기능을 볼 수 없다.** 데모 계정을 주지 않으면
Guideline 2.1(불완전한 정보)로 거절된다.

| 항목 | 값 |
|---|---|
| 사용자 이름 | `(심사용 데모 계정 이메일)` |
| 암호 | `(심사용 데모 계정 비밀번호)` |
| 연락처 | 이름 / 전화 / 이메일 |

**데모 계정 준비 시 확인할 것**
- 이메일 인증이 **완료된** 상태여야 한다 (미인증이면 로그인 자체가 막힌다)
- 명함 1~2장, 명함첩 항목 몇 개, 그룹 1개를 미리 넣어 빈 화면을 피한다
- 심사 기간 동안 비밀번호를 바꾸거나 계정을 잠그지 않는다

**심사 메모 예시**

```
ELID는 디지털 명함을 만들고 QR/링크로 교환하는 비즈니스 네트워킹 앱입니다.
첨부한 데모 계정으로 로그인하면 명함 생성·QR 공유·명함첩·그룹·채팅을
모두 확인하실 수 있습니다.

[구독 결제] 현재 버전에서는 구독 결제 경로가 서버에서 비활성화되어 있습니다.
플랜 업그레이드 화면은 볼 수 있으나 결제를 시도하면 "준비 중" 안내가 표시되며
실제 과금은 발생하지 않습니다.
```

### 2-4. 앱 개인정보(App Privacy) 설문

**`ios/Runner/PrivacyInfo.xcprivacy`와 답변이 어긋나면 리젝 사유가 된다.**
그 파일을 기준으로 아래와 같이 답한다.

| 데이터 | 수집 | 사용자 신원 연결 | 추적 | 목적 |
|---|---|---|---|---|
| 이메일 주소 | 예 | 예 | 아니오 | 앱 기능 |
| 이름 | 예 | 예 | 아니오 | 앱 기능 |
| 전화번호 | 예 | 예 | 아니오 | 앱 기능 |
| 실제 주소 | 예 | 예 | 아니오 | 앱 기능 (NFC 명함 배송) |
| 사진 | 예 | 예 | 아니오 | 앱 기능 (프로필/명함 사진) |
| 기타 사용자 콘텐츠 | 예 | 예 | 아니오 | 앱 기능 (회사·직함·채팅) |
| 사용자 ID | 예 | 예 | 아니오 | 앱 기능 |

**추적(Tracking)은 전부 "아니오"** — 광고 SDK나 제3자 추적을 넣지 않았다.

## 3. 스크린샷

iPhone 전용이므로 **6.7"(1290×2796) 한 세트**면 등록이 가능하다.
(6.5"는 6.7" 이미지를 그대로 재사용할 수 있다.)

| # | 화면 | 강조할 것 |
|---|---|---|
| 1 | 명함 상세 | 브랜드 디자인 — 첫인상 |
| 2 | 명함 목록 / 디자인 선택 | 24종 템플릿 |
| 3 | QR 공유 | 교환이 얼마나 쉬운지 |
| 4 | 명함첩(네트워크) | 쌓이는 인맥 |
| 5 | 그룹 / 채팅 | 지속되는 관계 |

- 상태바가 깨끗한 시뮬레이터에서 촬영한다
- **한국어 스크린샷만으로 제출 가능** (기본 언어를 한국어로 설정)

## 4. 리젝 대응 — 이 앱에서 실제로 걸릴 만한 것

| 사유 | 원인 | 대응 |
|---|---|---|
| **2.1 불완전** | 데모 계정 누락·로그인 실패 | 위 2-3 확인. 이메일 인증 완료 여부가 흔한 함정 |
| **3.1.1 인앱결제** | 외부 결제 유도 | 포인트 충전이 외부 브라우저로 나간다. **디지털 재화 구매로 보이면 문제가 된다** — 심사 메모에 용도를 명확히 쓰고, 지적받으면 해당 진입점을 숨기는 빌드로 대응 |
| **5.1.1 개인정보** | 처리방침 URL 미응답 / 설문 불일치 | 2-2, 2-4 확인 |
| **4.0 디자인** | 동작하지 않는 UI | 소셜 로그인 버튼·설정 아이콘은 이미 제거했다. "준비 중"만 뜨는 요소가 더 없는지 제출 전 확인 |
| **2.3.1 숨은 기능** | 제휴 웹뷰 | 해피트리 진입은 정상 기능이다. 심사 메모에 제휴 서비스임을 설명 |

> **3.1.1이 이 앱의 최대 위험이다.** 포인트 충전을 외부 웹으로 보내는 구조라
> 심사자가 "인앱결제 우회"로 볼 여지가 있다. 첫 제출에서 이걸로 걸리면
> 포인트 충전 진입점을 iOS 빌드에서만 감추는 것이 가장 빠른 통과 경로다.
